# Build targets for iOS, Mac Catalyst, macOS and tvOS

The following build targets are defined in .NET for iOS, Mac Catalyst, macOS, and tvOS projects.

## Build (Default)

Builds the source code within a project and all dependencies.

## Clean

Removes all files generated by the build process.

## ComputeAvailableDevices

Queries and returns a list of available iOS or tvOS devices and simulators that can be used with `dotnet run`.

This target is called automatically by the .NET SDK's `dotnet run` command to
support device selection via the `--device` option. It returns a `@(Devices)`
item group where each device has the following metadata:

- **Description**: The name of the device (e.g., "iPhone 16 - iOS 26.0" for simulators, "My iPhone 16" for physical devices)
- **Type**: Either "Device" or "Simulator"
- **OSVersion**: The OS version of the device
- **UDID**: The UDID of the device
- **RuntimeIdentifier**: The RuntimeIdentifier of the device

For example, to list all available devices:

```shell
$ dotnet build -t:ComputeAvailableDevices
```

This target is part of the [.NET SDK device selection specification](https://github.com/dotnet/sdk/blob/2b9fc02a265c735f2132e4e3626e94962e48bdf5/documentation/specs/dotnet-run-for-maui.md) and enables commands like:

```shell
$ dotnet run --device UDID
```

On Windows, the devices are queried on the remote Mac using the remote build
connection. As with remote builds, this requires a password or an encrypted
SSH key; SSH-agent identities and unencrypted keys aren't supported.

Added in .NET 11.

## ConfigureMac

Prepares an Apple silicon Mac for remote iOS builds. Windows is the supported
client; a Mac can also connect to itself over SSH for development. The client
must have the iOS workload and a .NET 12 SDK at least as recent as
`12.0.100-alpha.1.26523.103`.
The target checks Xcode and the iOS simulator runtimes, but does not install
them or change the selected Xcode. Set `XcodeLocation` to check a different
Xcode on the Mac.

For example:

```shell
dotnet msbuild MyApp.csproj -t:ConfigureMac -p:ServerAddress=mac.example.com -p:ServerUser=remote-user -p:ServerPasswordFile=C:\private\mac-password.txt
```

Wrapper projects must invoke `ConfigureMac` on the iOS project so it uses
that project's workload configuration. The target returns the remote SDK path,
which a wrapper can capture from `TargetOutputs`.

`ServerPasswordFile` is the path to a protected UTF-8 file on the client.
Do not pass passwords or key passphrases as MSBuild properties or environment
variables: MSBuild can record them in logs and binlogs. The target also supports
SSH-agent identities and key files supplied with `SSHKey`. For an encrypted
key, set `SSHPassPhraseFile` to a protected file on the client. The same
property can be used for remote builds. SSH-agent identities and unencrypted
keys work only with `ConfigureMac`; remote builds require a password or an
encrypted key. On Windows, SSH-agent support requires the OpenSSH agent;
Pageant is not supported.

The Mac's host key must be in the client's SSH known-hosts file. Alternatively,
set `ServerFingerprint` to the expected SHA256 fingerprint. Use `ServerSshPort`
if the Mac uses a port other than 22.

The target installs a matching .NET SDK, iOS workload, and build agents under
`~/Library/Caches/maui/PairToMac` by default. Set `RemoteBasePath` to use a
different directory. `RemoteNuGetConfigFile` can specify a NuGet configuration
file already on the Mac. Existing XMA NuGet configuration files are preserved
unless `OverwriteRemoteNuGetConfig` is set to `true`. If an existing file
differs, the target fails rather than replacing it. `ResetRemoteCache` removes
the existing XMA cache when set to `true`; it is `false` by default.

The resulting `RemoteDotNetRoot`, `RemoteHomeDirectory`, `RemoteArchitecture`,
and `ConfiguredRemoteBasePath` properties are available after the target runs.
For example, add `-getProperty:RemoteDotNetRoot` to print the remote SDK path.
Run the build in a separate MSBuild invocation and pass that path as
`RemoteDotNetRoot`. If you set `RemoteBasePath`, pass it to the build too.
Escape any `%` characters in these property values as `%25` when passing them
to MSBuild.

### Testing local ConfigureMac changes

When building dotnet/macios from source, set `MESSAGING_REMOTE_REPO` to an
absolute path to a dotnet-macios-devtools checkout:

```shell
export MESSAGING_REMOTE_REPO="/path/to/dotnet-macios-devtools"
make -C msbuild all install
```

Normal dotnet/macios builds also honor this variable. Each build packs a fresh
`Xamarin.Messaging.Remote` version, prints its path and version, and updates the
installed SDK's ConfigureMac files. The devtools checkout must support
`make -C remote pack PACKAGE_PATH_FILE=...`. Build or pack failures stop the
macios build; an older package is never selected instead.

Tracked feeds and package versions stay unchanged. Unset the variable and
build again to return to the tracked package:

```shell
unset MESSAGING_REMOTE_REPO
make -C msbuild all install
```

To configure this Mac over SSH using the workload packages already built in
`_build/nupkgs`, run:

```shell
make -C msbuild install-remote-locally
```

This copies the packages into `_build/feed`, creates `_build/feed/NuGet.config`
with that feed and the repository's feeds, and passes the config to
`ConfigureMac`. **This resets the local XMA cache** before installing the SDK,
workload, and agents.

## DeployToDevice

Deploys an already-built iOS or tvOS app to a device or simulator without
building it again. A specific deployment target can be selected with the
`$(Device)` property.

```dotnetcli
dotnet build -t:DeployToDevice project.csproj -p:Device=<udid>
```

The .NET SDK calls this target during `dotnet run`, including when the
`--no-build` option is specified.

Hot Reload startup hooks are copied to a physical device when computing launch
arguments, after deployment. Calling `DeployToDevice` alone does not prepare
the startup hooks or the Hot Reload launch environment.

Added in .NET 11.

## GetApplicationArtifacts

Builds the project and returns the `@(ApplicationArtifact)` item group. This
target always runs `Build` first so platform `.app`, `.ipa`, `.pkg`, and
`.xcarchive` artifacts are produced and collected before any custom metadata
extension targets run. The `Publish` target returns the same item group for
artifacts it creates.

The returned item group reflects the artifacts the current invocation is
configured to build; it does not scan for `.ipa`, `.pkg`, or `.xcarchive` files
left on disk by a previous build. The `.app` bundle is always collected for an
application project (excluding app extension and watch app projects), while the
`.ipa`, `.pkg`, and `.xcarchive` outputs are only collected when
[BuildIpa](build-properties.md#buildipa),
[CreatePackage](build-properties.md#createpackage), or
[ArchiveOnBuild](build-properties.md#archiveonbuild) (respectively) is enabled in
the same invocation. The `Publish` target enables `BuildIpa` (mobile) or
`CreatePackage` (desktop) by default.

```shell
$ dotnet build MyApp.csproj -t:GetApplicationArtifacts -getItem:ApplicationArtifact
$ dotnet build MyApp.csproj -t:Publish -getItem:ApplicationArtifact
```

See [ApplicationArtifact](build-items.md#applicationartifact) for supported metadata.

Targets that need to add or update `@(ApplicationArtifact)` metadata before
`GetApplicationArtifacts` or `Publish` returns can append to
[GetApplicationArtifactsDependsOn](build-properties.md#getapplicationartifactsdependson).

## Run

Builds the source code within a project and all dependencies, and then deploys and runs it
on a default simulator/device. A specific deployment target can be set by using the `$(Device)` property.

```dotnetcli
dotnet build -t:Run project.csproj -p:Device=<udid>
```

## StreamDeviceLog

Streams the system log of an iOS device or simulator on a remote Mac to the
caller through a named pipe. Set [`Device`](build-properties.md#device) to the
UDID or name of the device, and
[`DeviceLogPipeName`](build-properties.md#devicelogpipename) to the name of
the pipe.

This is a long-running target. It uses the same connection and authentication
properties as [`ConfigureMac`](#configuremac): an SSH key, then the SSH agent,
then a password file. It also uses the same pipe and message format as
[`SubscribeToDeviceUpdates`](#subscribetodeviceupdates), except that:

- `Ready` has a `device` field instead of `devices`.
- There are no `Update` messages. Each log line is sent as a `Log` message
  instead:

  ```json
  {"version":1,"type":"Log","log":{"raw":"...","date":"...","deviceName":"...","tag":"...","pid":123,"level":"...","message":"..."}}
  ```

  Only `raw` is always present. The other fields are omitted when the line
  can't be parsed. `pid` is a number; the other fields are strings.

A simulator must be booted, and a physical device must be connected to the Mac
with USB (and unlocked). Otherwise the target fails with a fatal `Error`.

If the caller reads too slowly, log lines are dropped and a non-fatal `Error`
message is sent.

```shell
DOTNET_CLI_USE_MSBUILD_SERVER=0 dotnet build MyApp.csproj -f net12.0-ios -t:StreamDeviceLog -nodeReuse:false -p:DeviceLogPipeName=<pipe-name> -p:Device=<udid> -p:ServerAddress=mac.example.com -p:ServerUser=remote-user
```

Added in .NET 12.

## SubscribeToDeviceUpdates

Sends the list of available devices and simulators to the caller through a
named pipe, and sends the list again whenever it changes. The list is the same
as the one returned by [`ComputeAvailableDevices`](#computeavailabledevices).
Set [`DeviceUpdatesPipeName`](build-properties.md#deviceupdatespipename) to
the name of the pipe.

This is a long-running target: it only returns once the caller stops it.
Run it in its own MSBuild invocation, and disable node reuse and the MSBuild
server so the process ends with the target. Don't run it from inside an IDE's
build:

```shell
DOTNET_CLI_USE_MSBUILD_SERVER=0 dotnet build MyApp.csproj -f net12.0-ios -t:SubscribeToDeviceUpdates -nodeReuse:false -p:DeviceUpdatesPipeName=<pipe-name> -p:ServerAddress=mac.example.com -p:ServerUser=remote-user
```

The target uses the same connection and authentication properties as
[`ConfigureMac`](#configuremac): an SSH key, then the SSH agent, then a
password file. Each list of devices is computed by running
`ComputeAvailableDevices` on the project, so on Windows the properties needed
for remote builds, such as `RemoteDotNetRoot` and a password or an encrypted
key, must be set too. `TargetFramework`, `Configuration`, and a
`RuntimeIdentifier` set by the user are passed to `ComputeAvailableDevices`.

### Pipe

The caller creates the pipe server before starting the build. Use a random
name, and only allow the current user to connect. In .NET:

```csharp
var pipe = new NamedPipeServerStream (name, PipeDirection.InOut, 1, PipeTransmissionMode.Byte, PipeOptions.Asynchronous | PipeOptions.CurrentUserOnly);
```

The target connects to the pipe as a client, and fails if it can't connect
within 30 seconds. The name is a pipe name, not a path.

### Messages

Messages are UTF-8 JSON objects, one per line (each line ends with `\n`, and
is at most 1 MiB). Every message has `"version":1` and a `type`. Ignore fields
and messages you don't recognize.

The target sends these messages:

| Type      | When                                                         | Fields                                    |
|-----------|--------------------------------------------------------------|-------------------------------------------|
| `Started` | First, right after connecting to the pipe, before connecting to the Mac. | `operation`: `DeviceUpdates` or `DeviceLog` |
| `Ready`   | Once, when the subscription is active.                       | `devices`: the full list of devices        |
| `Update`  | Whenever the list of devices changes.                        | `devices`: the full list of devices        |
| `Error`   | When something fails.                                        | `code`, `message`, `fatal`                 |
| `Ended`   | Last, if the pipe is still open.                             | `reason`: `Stopped`, `Disconnected`, `Failed` or `Completed` |

Each device has the same item spec and metadata as the `@(Devices)` items
returned by `ComputeAvailableDevices`. Metadata values are strings:

```json
{"version":1,"type":"Ready","devices":[{"itemSpec":"<udid>","metadata":{"Description":"iPhone 16 - iOS 26.0","Type":"Simulator","UDID":"<udid>"}}]}
```

Wait for `Ready` before using the list; the target doesn't return when it's
ready. A non-fatal `Error`, for example when a list couldn't be computed,
doesn't stop the subscription. A fatal `Error` is followed by `Ended` with the
reason `Failed`, and the build fails.

To stop the target, send `{"version":1,"type":"Stop"}` or close the pipe. This
works at any time, including while connecting to the Mac. If a list of
devices is being computed, the target stops once it's done. The target then
disconnects within 10 seconds and the build succeeds.

The target checks the output of `simctl` and `devicectl` on the Mac for
changes every 3 seconds; it doesn't receive notifications from the Mac. Updates
can therefore take a few seconds to arrive, and a change that is undone within
3 seconds might not be reported.

Added in .NET 12.
